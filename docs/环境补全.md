# PA Player · 环境补全与构建说明

这份文档解决一件事：**从一台什么都没装的机器，做到能出 debug / release / vision 三个包，并且能自己验证包是对的。**

项目在 `/workspace/PA-Player`。Android 应用，Kotlin + Jetpack Compose，minSdk 33。

---

## 0 一页速查

```bash
cd /workspace/PA-Player

./build.sh debug          # 出调试包
./build.sh release        # 出正式包
./build.sh vision         # 出实验包
./build-all.sh            # 三个一起出，共用同一个版本号
./build.sh release --info # 排障：看依赖下载和编译器参数

python3 tools/apk-info.py dist/*.apk   # 验证包名/版本/minSdk
```

产物在 `dist/PA-Player-<变体>-<版本>.apk`。

## 1 版本矩阵（锁死，不要"顺手升级"）

| 组件 | 版本 | 备注 |
|---|---|---|
| JDK | 21 | AGP 9 要 17 以上，用 21 |
| Gradle | 9.8.0 | AGP 9.4 要求 Gradle 9.x |
| AGP（Android Gradle Plugin） | 9.4.1 | |
| Kotlin | 2.4.21 | **由 AGP 内置，不要在构建脚本里声明** |
| Compose 编译器插件 | 2.4.21 | **必须等于上面的 Kotlin 版本** |
| Compose BOM | 2026.09.00 | |
| compileSdk | 37 | |
| minSdk | 33 | |
| targetSdk | 37 | |
| build-tools | 37.0.0 | |
| Android 平台包 | `android-37.0` | **目录名带小版本，不是 `android-37`** |

为什么锁死：从 AGP 9 开始 Kotlin 编译器随 AGP 一起发布，Kotlin 版本不再由你指定；而 Compose 编译器插件必须与那个 Kotlin 版本**逐个对齐**，写错会在配置阶段直接失败（不是编译期）。

## 2 装环境

### 2.1 JDK 21

```bash
sudo apt install -y openjdk-21-jdk
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-arm64   # x86 机器是 java-21-openjdk-amd64
```

### 2.2 Gradle 9.8.0

两条路，选一条：

**甲 · 用 wrapper（推荐给新机器）**
项目里已经带 `gradlew`。第一次执行会自动下载 Gradle 9.8.0 发行版（约 130 MB），之后本地缓存。

**乙 · 装一份固定的**
从 <https://services.gradle.org/distributions/> 取 `gradle-9.8.0-bin.zip`，解压到任意目录，把 `bin/` 加进 PATH。
`build.sh` 会优先用 `/opt/gradle/gradle-9.8.0/bin/gradle`，没有才用 PATH 里的，再没有才用 `./gradlew`。换机器时这个优先级你可能要调。

### 2.3 Android SDK

```bash
export ANDROID_HOME=$HOME/android-sdk
mkdir -p "$ANDROID_HOME/cmdline-tools"

# 下载 commandlinetools-linux-*.zip 后：
unzip commandlinetools-linux-*.zip -d /tmp/clt
mv /tmp/clt/cmdline-tools "$ANDROID_HOME/cmdline-tools/latest"

SDKM="$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager"
yes | "$SDKM" --licenses
"$SDKM" --sdk_root="$ANDROID_HOME" \
  "platform-tools" "platforms;android-37.0" "build-tools;37.0.0"
```

如果 `sdkmanager` 说找不到 `platforms;android-37.0`，加 `--channel=2` 走预览通道再试一次。

### 2.4 环境变量

```bash
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-arm64
export ANDROID_HOME=$HOME/android-sdk
export PATH="$ANDROID_HOME/platform-tools:$PATH"
```

`build.sh` 里已经写了默认值（`JAVA_HOME` 指 arm64 那份、`ANDROID_HOME=/opt/android-sdk`）。换机器时要么改这两行，要么在执行前 export 好——**export 优先，脚本不会覆盖已有值**。

## 3 ARM64 机器必须多做一步：aapt2 包装

AGP 从 Maven 取 `aapt2`，那是 **x86_64 的 ELF 可执行文件**。

- **x86_64 机器（Intel/AMD 的 Linux、Windows、macOS Intel）**：什么都不用做，删掉 `gradle.properties` 里 `android.aapt2FromMavenOverride` 那一行即可。
- **ARM64 机器（aarch64：Apple Silicon、树莓派、ARM 服务器、ARM 容器）**：必须用 qemu 包一层，否则构建报 `AAPT2 ... Daemon startup failed` 或直接 `Exec format error`。

做法：

```bash
sudo apt install -y qemu-user-static

# 取出真正的 aapt2（两种来源都可以）
# 甲：从 build-tools
cp "$ANDROID_HOME/build-tools/37.0.0/aapt2" ~/android-tools/aapt2-real
# 乙：从 gradle 缓存里的 aapt2 jar
# unzip -o -q ~/.gradle/caches/modules-2/files-2.1/com.android.tools.build/aapt2/9.4.1-*/*-linux.jar aapt2 -d ~/android-tools

mkdir -p ~/android-tools/wrap
cat > ~/android-tools/wrap/aapt2 <<'SH'
#!/bin/sh
exec qemu-x86_64 /home/YOUR_USER/android-tools/aapt2-real "$@"
SH
chmod +x ~/android-tools/wrap/aapt2
```

然后在 `gradle.properties` 里（项目里已经有这行，改成你的路径）：

```properties
android.aapt2FromMavenOverride=/home/YOUR_USER/android-tools/wrap/aapt2
```

两个细节，踩过才知道：

- **包装脚本的文件名必须正好叫 `aapt2`**。AGP 只按名字找，并检查「是不是可执行文件」，名字叫 `aapt2-qemu` 会被拒，报 `Custom AAPT2 location does not point to an AAPT2 executable`。
- 包装脚本里**不要**加 `exec -a` 之类的花活，`exec qemu-x86_64 <真实路径> "$@"` 就够；daemon 模式也能跑。

## 4 六个已知坑

**① 不要加 `org.jetbrains.kotlin.android` 插件。**
AGP 9 起内置 Kotlin 支持，加了会在配置阶段直接失败：
`The 'org.jetbrains.kotlin.android' plugin is no longer required for Kotlin support since AGP 9.0.`

**② Compose 编译器插件仍然要单独加。**
`id("org.jetbrains.kotlin.plugin.compose") version "2.4.21"`，版本必须与 AGP 内置的 Kotlin 一致。缺了会报
`Starting in Kotlin 2.0, the Compose Compiler Gradle plugin is required when compose is enabled.`

**③ `resValue` 默认是关的，而且和 `initWith` 打架。**
本项目改用 `manifestPlaceholders["appLabel"]`，manifest 里写 `android:label="${appLabel}"`，三个变体各自给桌面名。不要改回 `resValue`，否则会同时撞上「feature is disabled」和「value is being replaced」两个问题。

**④ `aapt2 dump` 在 ARM64 + qemu 下会 SIGILL（`Illegal instruction`，返回码 132）。**
编译、链接、打包全部正常，只有 `dump` 子命令崩溃。所以查包信息**不要用 `aapt2 dump badging`**，用项目自带的：

```bash
python3 tools/apk-info.py dist/PA-Player-release-*.apk
```

`tools/apk-info.py` 自己解析二进制 `AndroidManifest.xml`，只依赖标准库，能在任何环境跑。

**⑤ 版本号必须按北京时间取。**
如果构建机是 UTC（容器里很常见），直接 `date` 会得到比北京时间早 8 小时的值。`app/build.gradle.kts` 里已经固定 `TimeZone.getTimeZone("Asia/Shanghai")`，**不要删**。

**⑥ `versionCode` 不能直接用时间戳。**
格式 `YYMMDDHHmm` 是 10 位，例如 `2611151551`，值大于 Android 的 int 上限 `2147483647`，编译直接失败。当前做法是**减 20 亿**：`2611151551 → 611151551`。跨年跨月仍然单调递增。改这段逻辑前先想清楚递增性。

## 6 验证：不要只信"编译通过"

出包之后必须过这四关。

```bash
# ① 包名 / 版本 / minSdk / 桌面名
python3 tools/apk-info.py dist/*.apk
```

期望：

| 包 | 包名 | 桌面名 |
|---|---|---|
| debug | `me.cwre.player.debug` | PA Player Debug |
| release | `me.cwre.player` | PA Player |
| vision | `me.cwre.player.vision` | PA Player V |

三个的 `minSdk` 都是 `33`。

```bash
# ② 签名：三份必须互不相同
APKSIGNER=$ANDROID_HOME/build-tools/37.0.0/apksigner
for f in dist/*.apk; do "$APKSIGNER" verify --print-certs "$f" | head -2; done
```

三个证书的 `SHA-256` 必须两两不同。若出现相同，说明变体误用了同一把密钥，必须停下修。

```bash
# ③ 装得上
# 用文件管理器把 apk 导到手机「下载」目录，点开安装。三个包可以同时装。

# ④ 打开看一眼
# 首页会直接写出「变体 / 包名 / 版本」，确认和上表一致。
```

## 7 三个变体与密钥

| 变体 | 包名 | 桌面名 | 密钥文件 | 用途 |
|---|---|---|---|---|
| debug | `me.cwre.player.debug` | PA Player Debug | `keystore/pa-debug.jks` | 日常开发 |
| release | `me.cwre.player` | PA Player | `keystore/pa-release.jks` | 正式发布 |
| vision | `me.cwre.player.vision` | PA Player V | `keystore/pa-vision.jks` | 试验性改动，独立装 |

- 三把密钥**互不复用**，RSA 4096，有效期 30 年。
- 密码与别名在 `keystore/keystore.properties`，与 `.jks` 一起被 `.gitignore` 排除，**不进版本库、不进任何交付包**。
- 这三个文件必须单独备份。**丢了就永远无法覆盖安装**，只能让用户卸载重装、数据清零。
- 换机器时把 `keystore/` 整个目录拷过去，`app/build.gradle.kts` 会自动读。

## 8 代码约束

写代码前先看这几条，它们不是风格偏好，是这个项目刻意选的方向。

1. **只用 Compose，不用 layout XML。** 全项目唯一的 XML 是 `app/src/main/res/values/styles.xml`，只负责把窗口底色设成黑，避免启动白闪。
2. **色值、字号、间距、圆角、时长只能从 `ui/theme/Tokens.kt` 取。** 别处出现 `Color(0xFF…)`、`14.sp`、`12.dp` 就算错。要新值先往 Tokens 里加，别就地写死。
3. **主色未定。** `Palette.accent` 现在是中性白占位，等所有者定。不要自己挑一个"好看的颜色"填进去。
4. **不引 UI / 效果库。** 需要玻璃、模糊、光晕这类效果时，先说清它解决了什么具体问题，再决定自己写还是引库。上一个项目就是"到处都是胶囊配白描边发光"把自己做废的。
5. **注释只写为什么，不写是什么。** `// 初始化` 这种一律不要；只有"这里为什么必须这么写"才值得留一行。
6. **标识符英文，界面文案中文。** 目前没有做多语言的打算，不要提前铺 `strings.xml`。

---

## 9 交接边界

- 不要改 `keystore/` 里的任何文件。
- 不要动 `app/build.gradle.kts` 里的**三个变体定义**和**版本号生成规则**，除非明确要求。
- `dist/`、`build/`、`.gradle/` 都是产物，不进版本库。
- 改完之后必须跑第 6 节的四关验证，别只贴一句"编译通过"。

## 10 目录结构

```
PA-Player/
├── build.sh                     单变体出包，带实时任务打印和汇总
├── build-all.sh                 三个变体共用版本号
├── gradlew / gradle/            wrapper（新机器可直接用）
├── gradle/libs.versions.toml    依赖版本集中在这
├── gradle.properties            JVM 内存、aapt2 覆盖（ARM64 才需要）
├── keystore/                    三把密钥 + 密码，不入库
├── tools/apk-info.py            解析 APK 的二进制 manifest
├── docs/环境补全.md              本文件
├── dist/                        出包结果
└── app/
    ├── build.gradle.kts         变体、签名、版本号规则
    └── src/main/
        ├── AndroidManifest.xml
        ├── java/me/cwre/player/
        │   ├── MainActivity.kt
        │   └── ui/theme/{Tokens.kt, Theme.kt}
        └── res/values/styles.xml
```

目前只有 3 个 Kotlin 文件，是个空壳：一个黑底页面，写着应用名、变体、包名、版本号，用来确认装的是哪个包。真正的功能还没开始写。
